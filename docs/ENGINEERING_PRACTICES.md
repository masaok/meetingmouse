# Engineering practices

The 31 techniques from [Engineering Practices That Survive the Stack](https://www.masao.site/code-quality/engineering-practices),
audited against this repository. Adopted items name the file that implements them; rejected
items keep their reasoning so the same proposal does not return in six months.

## Adopted

| #   | Technique                                     | Here                                                                                                                                                                                                                                                                |
| --- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1 | Hosted CI, separate named jobs                | `.github/workflows/ci.yml`: read-only permissions, cancel-in-progress, SHA-pinned actions, frozen lockfile                                                                                                                                                          |
| 1.2 | Staged-files-only pre-commit                  | `.husky/pre-commit` → `lint-staged` → `prettier --write`; pre-push → `pnpm typecheck`                                                                                                                                                                               |
| 1.3 | Read-only lint in automation                  | `lint` / `format:check` in hooks and CI; `lint:fix` / `format` are manual                                                                                                                                                                                           |
| 1.4 | Required status checks                        | Six job names listed in [Deployment](./DEPLOYMENT.md#required-status-checks)                                                                                                                                                                                        |
| 1.5 | Host-faithful production build                | `Production build` job on Node from `.nvmrc`, frozen lockfile, **and no env vars**: an early Vercel preview failed because `db/client.ts` read env at import time while local and CI builds had fake values; the client is now lazy and the CI build job has no env |
| 2.1 | Compiler-enforced server boundary             | `import "server-only"` in `src/db/client.ts`, `src/bolt/app.ts`; ESLint fallback                                                                                                                                                                                    |
| 2.2 | Every config has its tool running             | Prettier (+ sort-imports, tailwind plugins) declared and run in CI                                                                                                                                                                                                  |
| 2.3 | Guides describe the code that exists          | `AGENTS.md`, `CONTRIBUTING.md`, PR template; `docs/` is link-checked so a stale path fails CI                                                                                                                                                                       |
| 3.1 | One runtime version                           | `.nvmrc` = 24, `engines.node >= 22`, `@types/node` 24, CI reads `.nvmrc`                                                                                                                                                                                            |
| 3.2 | One composite setup step                      | `.github/actions/setup/action.yml`, pnpm version from `packageManager`                                                                                                                                                                                              |
| 3.3 | Derived constants                             | `SLOT_MINUTES` / `POLL_STATUSES` feed the DB checks, zod parsers and modals                                                                                                                                                                                         |
| 3.4 | Dependency automation respecting pins         | `.github/dependabot.yml`; `@types/node` and `typescript` majors held                                                                                                                                                                                                |
| 4.1 | Typegen inside typecheck                      | `typecheck` = `next typegen && tsc --noEmit`; CI regenerates migrations before diffing                                                                                                                                                                              |
| 4.2 | Proof-of-failure per custom check             | `tests/checks.test.ts` runs `check-docs` and `check-feature-map` on fixtures built to fail                                                                                                                                                                          |
| 4.3 | Import smoke test over real entry points      | `scripts/smoke-imports.ts` via `tsx --conditions=react-server`                                                                                                                                                                                                      |
| 5.1 | Numbered migrations, applied from empty in CI | `drizzle/0000_*.sql`, `Migrations apply from empty` job with a Postgres 17 service                                                                                                                                                                                  |
| 5.2 | Language-neutral migration format             | Plain SQL files; `drizzle-kit push` has no script on purpose                                                                                                                                                                                                        |
| 5.4 | One writer                                    | `pnpm db:migrate` only; nothing runs DDL at startup                                                                                                                                                                                                                 |
| 6.1 | Name the invariant before the vendor          | This table names the invariant; the file column names the tool                                                                                                                                                                                                      |
| 6.2 | Evaluate tools by failure mode                | The "Why not here" column in the rejected table names what would break here, not a missing feature                                                                                                                                                                  |
| 6.3 | Score bundled benefits one at a time          | The `vercel-slack build` row lists its three bundled costs separately instead of as one verdict                                                                                                                                                                     |
| 6.4 | Rejected items recorded                       | Below                                                                                                                                                                                                                                                               |
| 7.1 | Infra-dependent suites off the gate           | No live-Slack or live-Neon job is required; migrations use a disposable container                                                                                                                                                                                   |
| 7.3 | Env preflight at every entry point            | `src/lib/env.ts` `assertEnv`, called in the route and `scripts/check-dev-env.ts`                                                                                                                                                                                    |
| 7.4 | Living docs, link-checked                     | `docs/` + `pnpm docs:check`; `tests/checks.test.ts` proves the check fails on a broken fixture                                                                                                                                                                      |
| 7.5 | Remediation ordered by leverage               | Below                                                                                                                                                                                                                                                               |

## Explicitly NOT adopted

| #         | Technique                                                 | Why not here                                                                                                                                                      | What would flip it                                       |
| --------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 4.4 / 4.5 | Changed-files gate                                        | The whole gate runs in ~3 minutes; skip logic is untested code outside the gate and buys nothing yet                                                              | CI over ~10 min, or a large notes directory churning     |
| 5.3       | Harvest an accidental migration log                       | Nothing to harvest: the schema was born as migration 0000                                                                                                         | n/a                                                      |
| 5.5       | Advisory lock around the migration runner                 | Migrations are run deliberately by one human/CI step, never at startup or from daemons, so two runners cannot race                                                | Migrations at boot, or more than one deploy pipeline     |
| 7.2       | Port / resource registry                                  | Single operator; `next dev` picks a free port; worktrees for agents rarely run dev servers concurrently                                                           | A second concurrent human, or agents running e2e locally |
| ,         | Per-branch Slack apps for previews (`vercel-slack build`) | Needs a 12-hour-expiring configuration token, a Vercel API token in CI, and creates a Slack app per branch; previews are exercised with `pnpm slack:sign` instead | A reviewer audience that needs to click in Slack         |
| ,         | Biome instead of ESLint + Prettier                        | `eslint-config-next` carries the React/Next rules we want; the boundaries use `no-restricted-imports`                                                             | Biome gaining equivalent Next rules                      |
